## 一、产品概述

本 SDK 用于与「声云智能鼠标」硬件设备通信，封装了 **USB（HID）** 与 **BLE（蓝牙低功耗）** 两种连接方式下的设备发现、协议解析与音频解码能力，对外输出三类数据：

1. **原始按键事件** —— 哪个键 + 什么动作（按下/抬起/长按/单击），**不做任何业务映射**；
2. **离散事件** —— 设备信息（序列号/电量）、DPI 变更、会议状态等，以 JSON 字符串上报；
3. **音频数据** —— 支持两种输出模式（见「七、音频数据」）：默认解码为 **PCM**（16 kHz / 16 bit / 单声道），或透传 **原始编码块**（RAW）。

> **设计原则**：SDK 只负责「把硬件数据忠实搬运出来」，**所有业务逻辑由调用方自行实现**。例如 M 键按下后触发截图、语音转文字还是回车，由您的程序根据收到的 `keyEvent` 自行决定。这样 SDK 的对外接口可以长期保持稳定，硬件升级只需在 JSON 里新增字段。

### 工作模式

SDK 提供两种工作模式（`um_set_work_mode`）：

| 模式 | 宏 | 说明 |
|---|---|---|
| FULL | `UM_MODE_FULL`（默认） | 完整协议解析：SDK 解析按键/音频/SN/DPI/会议，经 `um_on_message` / `um_on_audio` 上报 |
| RAW | `UM_MODE_RAW` | 仅识别模式：SDK 不做任何协议解析，仅经 `um_on_raw_frame` 透传原始帧，上位机自行解析 |

**选择依据**：

- 硬件协议相同 → `FULL`；
- 音频芯片不同 → `RAW` + `um_set_audio_output_mode(UM_AUDIO_RAW)`；
- 硬件协议不同 → `RAW`，在 `um_on_raw_frame` 回调中自行处理，配合 `um_write_raw` 下发命令。

## 三、快速开始

最快的验证方式：编译运行仓库自带的 demo 源码（`demo/demo.c`，约 60 行最小示例），
确认硬件连接与数据通路正常。

### 3.1 Windows

解压 `packages/uMouseSdk_0.4.20_Windows_10-11_x64.zip`，在仓库根目录执行：

```bat
REM MSVC 开发者命令行
cl /I uMouseSdk\include demo\demo.c /Fe:demo.exe /link /LIBPATH:uMouseSdk uMouseSdk.lib

REM 运行前把包目录加入进程 PATH（DLL 所在目录不在系统默认搜索路径内）
set PATH=%CD%\uMouseSdk;%PATH%
demo.exe
```

（MinGW：`gcc -IuMouseSdk/include demo/demo.c -LuMouseSdk -luMouseSdk -o demo.exe`。
完整加载要点见包内 README：PATH 前插 / `LoadLibraryExW` + `LOAD_WITH_ALTERED_SEARCH_PATH` /
VC++ 运行库预载顺序。）

### 3.2 macOS

解压 `packages/uMouseSdk_0.4.20_macOS_11_arm64.zip`，在仓库根目录执行：

```bash
cc -IuMouseSdk/include demo/demo.c -LuMouseSdk -luMouseSdk -o demo
./demo
```

首次运行会请求蓝牙授权；USB（2.4G 接收器）连接即插即用。

## 四、集成到您的工程

本 SDK 为**纯 C ABI**，可被几乎所有主流语言直接调用。核心调用顺序：

> **注册回调 → `um_sdk_init()` → 业务处理 → `um_sdk_close()`**

> ⚠️ 回调**必须在 `um_sdk_init()` 之前注册**，否则可能错过设备连接等早期事件。

### 4.1 C / C++

**编译/链接方式：**

- 头文件：将包内 `include/` 加入头文件搜索路径；
- Windows（MSVC）：链接包内 `uMouseSdk.lib`，运行期把包目录内全部 DLL 与可执行文件同目录放置（或将包目录加入 `PATH`）；
- Linux：链接 `-luMouseSdk`（`-L<包>/lib`），并设置 `LD_LIBRARY_PATH` 或用 rpath `$ORIGIN`；
- macOS：链接 `-luMouseSdk`（`-L<包>/uMouseSdk`），用 `@loader_path` 作为 rpath。

**最小示例（FULL 模式）：**

```c
#include "umouse_sdk.h"
#include <stdio.h>

static void on_connected(const char* id, int mode) {
    printf("[连接] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_disconnected(const char* id, int mode) {
    printf("[断开] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_message(const char* id, const char* json) {
    printf("[事件] %s %s\n", id, json);
}
static void on_audio(const char* id, const unsigned char* pcm, int len) {
    /* pcm 仅在本回调期间有效，需要留存请立即 memcpy */
}

int main(void) {
    um_register_connected(on_connected);
    um_register_disconnected(on_disconnected);
    um_register_message(on_message);
    um_register_audio(on_audio);

    um_sdk_init(1);   /* debug=1 打开内部日志 */

    getchar();        /* 模拟业务运行 */

    um_sdk_close();
    return 0;
}
```

**RAW 模式示例（硬件协议与默认不同时）：**

```c
#include "umouse_sdk.h"

/* 仅 RAW 模式 + USB 通道生效：生成握手查询指令 */
static int build_probe(uint8_t* out, int max_len) {
    /* 返回实际字节数；返回 <=0 表示用默认查询指令 */
    return 0;
}
/* 仅 RAW 模式 + USB 通道生效：校验读回帧是否为有效回应 */
static int validate_resp(const uint8_t* buf, int len) {
    /* 返回 1=有效回应（设备在线），0=不是 */
    return 1;
}
/* 仅 RAW 模式 + BLE 通道生效：判断是否目标设备 */
static int match_device(const char* name, const char* address) {
    /* 返回 1=是目标设备（接管），0=不是（跳过） */
    return 1;
}
static void on_raw_frame(const char* id, const uint8_t* data, int len, int conn) {
    /* 设备上报的原始帧，自行解析 */
}

int main(void) {
    um_set_work_mode(UM_MODE_RAW);           /* init 前设置 */
    um_set_audio_output_mode(UM_AUDIO_RAW);  /* 如需原始编码块 */

    um_register_raw_frame(on_raw_frame);
    um_register_usb_build_probe(build_probe);
    um_register_usb_validate_resp(validate_resp);
    um_register_ble_match_device(match_device);

    um_sdk_init(1);
    getchar();
    um_sdk_close();
    return 0;
}
```

### 4.2 C# (.NET)

通过 **P/Invoke** 调用，无需任何第三方库。

```csharp
using System;
using System.Runtime.InteropServices;

internal static class UMouseSdk
{
    private const string DLL = "uMouseSdk";   // Linux: "libuMouseSdk.so"，macOS: "libuMouseSdk.dylib"

    public const int UM_CONN_USB = 0;
    public const int UM_CONN_BLE = 1;
    public const int UM_MODE_FULL = 0;
    public const int UM_MODE_RAW  = 1;
    public const int UM_AUDIO_PCM = 0;
    public const int UM_AUDIO_RAW = 1;
    public const int UM_CHAN_AUTO = 0;
    public const int UM_CHAN_USB  = 1;
    public const int UM_CHAN_BLE  = 2;

    public delegate void OnConnected(IntPtr deviceId, int connMode);
    public delegate void OnDisconnected(IntPtr deviceId, int connMode);
    public delegate void OnMessage(IntPtr deviceId, IntPtr json);
    public delegate void OnAudio(IntPtr deviceId, IntPtr pcm, int len);
    public delegate void OnRawFrame(IntPtr deviceId, IntPtr data, int len, int conn);

    [DllImport(DLL)] public static extern void um_sdk_init(int debug);
    [DllImport(DLL)] public static extern void um_sdk_close();
    [DllImport(DLL)] public static extern IntPtr um_sdk_version();

    [DllImport(DLL)] public static extern int um_set_work_mode(int mode);
    [DllImport(DLL)] public static extern int um_set_audio_output_mode(int mode);
    [DllImport(DLL)] public static extern int um_set_channel_pref(int pref);

    [DllImport(DLL)] public static extern void um_register_connected(OnConnected cb);
    [DllImport(DLL)] public static extern void um_register_disconnected(OnDisconnected cb);
    [DllImport(DLL)] public static extern void um_register_message(OnMessage cb);
    [DllImport(DLL)] public static extern void um_register_audio(OnAudio cb);
    [DllImport(DLL)] public static extern void um_register_raw_frame(OnRawFrame cb);

    [DllImport(DLL)] public static extern int um_get_device_count();
    [DllImport(DLL)] public static extern IntPtr um_get_device_id(int index);
    [DllImport(DLL)] public static extern int um_get_connection_mode(IntPtr deviceId);

    [DllImport(DLL)] public static extern int um_write_raw(IntPtr deviceId, byte[] data, int len);
    [DllImport(DLL)] public static extern int um_set_dpi(IntPtr deviceId, int level);
    [DllImport(DLL)] public static extern int um_meeting_create(IntPtr deviceId);
    [DllImport(DLL)] public static extern int um_meeting_destroy(IntPtr deviceId);
    [DllImport(DLL)] public static extern int um_meeting_pause(IntPtr deviceId);
    [DllImport(DLL)] public static extern int um_meeting_resume(IntPtr deviceId);

    public static string PtrToStringUtf8(IntPtr p) =>
        p == IntPtr.Zero ? null : Marshal.PtrToStringUTF8(p);
}
```

> **C# 关键提醒**：用于 P/Invoke 的委托实例**必须被持有**（存为字段或静态成员），否则 CLR 的 GC 会回收它，SDK 回调时将访问已释放的内存导致崩溃。

### 4.3 Python

使用标准库 `ctypes`：

```python
import ctypes
from ctypes import c_int, c_char_p, c_void_p, CFUNCTYPE

lib = ctypes.CDLL("./libuMouseSdk.so")   # 按平台改后缀

ON_CONNECTED = CFUNCTYPE(None, c_char_p, c_int)
ON_MESSAGE   = CFUNCTYPE(None, c_char_p, c_char_p)
ON_AUDIO     = CFUNCTYPE(None, c_char_p, c_void_p, c_int)

@ON_CONNECTED
def on_connected(device_id, mode):
    print(f"[连接] {device_id.decode()} via {'BLE' if mode else 'USB'}")

@ON_MESSAGE
def on_message(device_id, json):
    print(f"[事件] {device_id.decode()} {json.decode()}")

@ON_AUDIO
def on_audio(device_id, pcm, length):
    buf = ctypes.string_at(pcm, length)   # 立即拷出

lib.um_register_connected(on_connected)
lib.um_register_message(on_message)
lib.um_register_audio(on_audio)

lib.um_sdk_init(1)
print("SDK 版本:", lib.um_sdk_version().decode())

input("按回车退出...\n")
lib.um_sdk_close()
```

> **Python 关键提醒**：用 `@CFUNCTYPE` 装饰的回调对象必须**保持引用存活**（模块级变量即可），不要写成临时变量传给 register。

### 4.4 Electron / Node.js

推荐使用 [koffi](https://github.com/Koromix/koffi)：

```js
const koffi = require('koffi');
const lib = koffi.load('./libuMouseSdk.so');   // 按平台改后缀

const um_sdk_init    = lib.func('void um_sdk_init(int debug)');

const cb = koffi.register((id, json) => {
    console.log('[事件]', koffi.decode(id), JSON.parse(koffi.decode(json)));
}, koffi.pointer(OnMessage));

um_register_msg(cb);
um_sdk_init(1);
console.log('SDK 版本:', koffi.decode(um_sdk_version()));
```

## 五、API 参考

全部符号声明在 `umouse_sdk.h` 中，均为 `extern "C"`，符号统一前缀 `um_`。

### 5.1 生命周期

```c
void        um_sdk_init(int debug);
void        um_sdk_close(void);
const char* um_sdk_version(void);
void        um_enable_crash_report(int enable);
```

| 函数 | 说明 |
|---|---|
| `um_sdk_init` | 初始化并启动 SDK（内部启动设备监测与各设备的解析/音频解码线程，事件经统一派发线程回调）。`debug != 0` 时开启内部日志。**注册回调应在调用之前完成**。 |
| `um_sdk_close` | 停止并释放 SDK 内部资源（幂等，可重复调用）。程序退出前调用一次即可。 |
| `um_sdk_version` | 返回版本号字符串（如 `"0.4.20"`），静态字符串，整个生命周期有效。 |
| `um_enable_crash_report` | 进程级崩溃记录开关，**默认开启**。开启时进程发生未处理崩溃会在**当前工作目录**写 `umouse_crash-<时间戳>.log`（异常码、故障地址、故障模块、原始调用栈、SDK 版本，保留最近 10 份，超量旧日志在下次 `um_sdk_init` 时清理）。仅技术诊断信息，不含 token/SN 等业务数据。`enable=0` 关闭；可在 `um_sdk_init` 前或运行中随时调用，立即生效。宿主程序自带崩溃捕获（如 Breakpad/crashpad）时可关闭本功能避免双写。 |

### 5.2 配置

```c
/* 音频输出模式 */
#define UM_AUDIO_PCM 0   /* 内置解码为 PCM：16kHz/16bit/单声道（默认），支持 ADPCM/SBC */
#define UM_AUDIO_RAW 1   /* 原始编码累积块：未经解码（每 256B 一块），由调用方解码 */
int um_set_audio_output_mode(int mode);

/* 工作模式 */
#define UM_MODE_FULL 0   /* 完整协议解析（默认规则默认值） */
#define UM_MODE_RAW  1   /* 仅识别：透传原始帧，不做协议解析（非默认规则默认值） */
int um_set_work_mode(int mode);
int um_set_work_mode_for(const char* rule_id, int mode);   /* 按规则设置（多设备，见 5.7） */

/* 同型号多台：一条规则最多同时接入的设备数（默认 4，1~8）。v0.4.0 起每台
 * 在线设备派生独立解析管线（按键/音频/SN/DPI/会议全解析）；达到上限后新
 * 发现的设备不再派生会话（静默不上线） */
int um_set_device_limit(const char* rule_id, int max_devices);

/* USB（2.4G 接收器）识别标识 */
struct um_usb_config {
    unsigned short vid;         /* 厂商 ID；0=默认 0xABC9 */
    unsigned short pid;         /* 产品 ID；0=默认 0xCA89 */
    int iface;                  /* 数据接口号；<0=不限接口 */
    unsigned char report_id;    /* HID report ID；0=默认 0x0A */
};
int um_set_usb_config(const char* rule_id, const struct um_usb_config* cfg);

/* 蓝牙识别标识 */
struct um_ble_config {
    const char* name;           /* 设备名精确匹配；NULL/空串=默认 "uMouse" */
    const char* mac_prefix;     /* MAC 前缀匹配（大小写不敏感）；NULL/空串=默认 "C0:88" */
    const char* service;        /* GATT service UUID；NULL/空串=默认 */
    const char* characteristic; /* GATT notify 特征 UUID；NULL/空串=默认 */
};
int um_set_ble_config(const char* rule_id, const struct um_ble_config* cfg);

/* 通道偏好（运行时可改） */
#define UM_CHAN_AUTO 0   /* USB 优先，静默超时后转 BLE（默认） */
#define UM_CHAN_USB  1   /* 仅探测 USB，永不转 BLE */
#define UM_CHAN_BLE  2   /* 仅探测 BLE，跳过 USB 接收器 */
int um_set_channel_pref(int pref);                        /* 作用于全部在线设备 */
int um_set_channel_pref_for(const char* device_id, int pref); /* 作用于指定设备 */
```

**关键时序约束**：

| 函数 | 调用时机 | 说明 |
|---|---|---|
| `um_set_work_mode` / `um_set_work_mode_for` | 仅 `um_sdk_init` 之前 | init 时锁定，之后返回 0；FULL 规则全局只能有一条 |
| `um_set_device_limit` | 仅 `um_sdk_init` 之前 | 同型号多台上限（默认 4，1~8；每设备独立管线） |
| `um_set_usb_config` | 仅 `um_sdk_init` 之前 | init 后返回 0；字段为 0 保留默认；rule_id 注册规则（见 5.7） |
| `um_set_ble_config` | 仅 `um_sdk_init` 之前 | init 后返回 0；字符串立即拷贝，调用方可随后释放 |
| `um_set_audio_output_mode` | 可在 init 之后随时切换 | 仅影响 `um_on_audio` 回调内容 |
| `um_set_channel_pref` / `um_set_channel_pref_for` | 仅 `um_sdk_init` 之后 | 运行时动作；切换瞬间断开当前通道并重新探测 |

> 所有返回 `int` 的配置函数：**`1` = 已采纳，`0` = 未采纳/参数非法**。

### 5.3 回调类型

```c
/* 设备连接。conn_mode: UM_CONN_USB / UM_CONN_BLE */
typedef void (*um_on_connected)(const char* device_id, int conn_mode);

/* 设备断开 */
typedef void (*um_on_disconnected)(const char* device_id, int conn_mode);

/* 离散事件，json 为 UTF-8 字符串（见「六、事件协议」） */
typedef void (*um_on_message)(const char* device_id, const char* json);

/* PCM 音频：16kHz/16bit/单声道小端。pcm 仅回调期间有效 */
typedef void (*um_on_audio)(const char* device_id, const uint8_t* pcm, int len);

/* 原始帧（RAW 规则全帧透传；FULL 规则每台设备亦对称透传，v0.4.0 起）。
 * data 仅回调期间有效 */
typedef void (*um_on_raw_frame)(const char* device_id, const uint8_t* data, int len, int conn);

/* USB 握手查询指令生成（仅 RAW 模式 + USB 通道生效）
 * 把握手字节填入 out，返回字节长度（<= max_len）；返回 <=0 用默认查询指令 */
typedef int (*um_usb_build_probe)(uint8_t* out, int max_len);

/* USB 握手回应帧校验（仅 RAW 模式 + USB 通道生效）
 * 返回 1=有效回应（设备在线），0=不是 */
typedef int (*um_usb_validate_resp)(const uint8_t* buf, int len);

/* BLE 目标设备识别（仅 RAW 模式 + BLE 通道生效）
 * 返回 1=是目标设备（接管），0=不是（跳过） */
typedef int (*um_ble_match_device)(const char* name, const char* address);
```

### 5.4 回调注册

```c
void um_register_connected(um_on_connected cb);
void um_register_disconnected(um_on_disconnected cb);
void um_register_message(um_on_message cb);
void um_register_audio(um_on_audio cb);
void um_register_raw_frame(um_on_raw_frame cb);                 /* RAW 模式生效 */
void um_register_usb_build_probe(um_usb_build_probe cb);         /* RAW 模式 USB 握手 */
void um_register_usb_validate_resp(um_usb_validate_resp cb);     /* RAW 模式 USB 校验 */
void um_register_ble_match_device(um_ble_match_device cb);       /* RAW 模式 BLE 识别 */
```

- 不需要的回调传 `NULL` 或不注册即可，SDK 不会因未注册而崩溃；
- `device_id` / `json` / `pcm` / `data` 等指针**仅在回调期间有效**，需要留存请立即拷贝；
- 注册应在 `um_sdk_init` 之前完成，以免错过早期事件。

### 5.5 设备查询（同步）

```c
int         um_get_device_count(void);          /* 当前已连接设备数（多设备模型） */
const char* um_get_device_id(int index);        /* 取第 index 个设备 id；越界返回 NULL */
int         um_get_connection_mode(const char* id); /* 0=USB 1=BLE；未连接返回 -1 */
```

> v0.3.0 多设备模型：`um_get_device_count()` 返回**已完成识别的在线设备数**；`device_id` 为设备 SN（或识别超时回退的临时身份，见 5.7）；`NULL` 表示"唯一在线设备"，多台在线时查询返回 -1 / 命令返回 0。

### 5.6 命令 / 请求

所有命令函数返回 `int`：**`1` = 命令已下发，`0` = 失败**（如未连接）。异步结果经 `um_on_message` 回调上报。

```c
/* 向指定设备的活动通道写原始字节（两种工作模式均可用）。
 * USB-HID 首字节通常需为 report_id（默认 0x0A），由调用方组装。
 * BLE 不应带 report_id 前缀。 */
int um_write_raw(const char* device_id, const uint8_t* data, int len);

int um_set_dpi(const char* device_id, int level);   /* 设置 DPI 档位（见下方注意） */

int um_meeting_create(const char* device_id);       /* 创建会议 */
int um_meeting_destroy(const char* device_id);      /* 结束会议 */
int um_meeting_pause(const char* device_id);        /* 暂停会议 */
int um_meeting_resume(const char* device_id);       /* 恢复会议 */
```

> `device_id` 为目标设备的 SN；`NULL` 仅在**恰好一台在线**时有效（单设备老宿主的兼容路径），
> 多台在线时返回 0——会话类操作（会议/DPI/写指令）在多设备下必须显式指定设备。
>
> **会议独占**：全局同一时刻只允许一台设备处于会议中。会议进行期间只有该设备可执行
> 会议操作，其它设备的会议指令在 SDK 层**拦截不下发**（返回 0），并向被拦截设备上抛
> `{"type":"meetingBusy","owner":"<占用者SN>"}`。归属随会议结束（`meetingDestroyed`）
> 或该设备断开而解除。v0.4.0 起每台设备独立解析管线，会议冲突仅此一种形态。
>
> **语音音频源先到先得**（默认策略）：多台设备同时采集时，首个出音频的设备占用
> 音频源直到其**单次采集结束**（语音键抬起收尾/设备离线），期间其它设备音频在
> SDK 层静音——keyEvent 照常上抛，由宿主自行提示"占用中"；下一次采集重新
> 先到先得。可用 `um_set_audio_source` 显式锁定某台设备（见 5.7）。
>
> **DPI 设置注意**：`um_set_dpi` 的 `level` 是**固件相关的档位字节**（协议 `03 22 <level>`），
> 不是 1..N 索引、也不是 DPI 数值——主流固件映射 {800→21, 1200→32, 1600→42,
> 2400→63, 4000→4, 6000→5}，其它固件族编码不同（如 0 基索引）。档位↔字节映射
> 由集成方按渠道/固件类型自建，SDK 只透传下发。固件对软件设置**不回执**：返回 1
> 仅代表已写入传输通道，生效与否看光标速度；`dpiChanged` 事件与软件设置无关（见 6.3）。
>
> `um_write_raw` 调用方需先经 `um_get_connection_mode` 判断当前通道，USB 带 report_id 前缀、BLE 不带（依目标设备协议）。

### 5.7 多设备接入（v0.3.0）

**设备模型**：

- **设备身份 = SN**。同一台设备的 USB / BLE 是它的两种连接方式，同一时间只激活一条；
  切换传输时设备身份连续（`device_id` 不变，`conn_mode` 属性变化）。
- **"设备类型"用规则（rule）描述**：`um_set_usb_config / um_set_ble_config / um_set_work_mode_for`
  的第一个参数 `rule_id` 注册一条规则。`NULL/""` = 默认规则（生产设备，FULL）；
  不同型号的设备各注册一条规则；**同型号多台共用一条规则，SDK 原生支持**——
  内置监测线程发现新设备（启动前在位/运行中热插拔）即为它派生独立会话线程，
  上限 `um_set_device_limit`（默认 4，范围 1~8；全局同时在线 8 台）。
- **同族多型号**：`um_usb_add_match(rule_id, &m)` 为一条规则追加 VID/PID 匹配项
  （vid/pid 必填非 0，iface/report_id 各项独立），须 init 前调用。
- **每设备独立解析管线（v0.4.0）**：每台在线设备（FULL/RAW 规则 alike）都派生
  自己的解析线程——按键/音频解码/SN/DPI/会议全解析，无主次之分；FULL 规则
  多台时每台的语音打字、会议、DPI 均完整可用。语音音频源默认先到先得锁存
  （本节末尾）；会议全局独占（见 5.6）。达到规则上限后新发现的设备静默不上线。
- **断开语义**（两种 USB 断开形态均由既有机制判定）：接收器拔出 = read 失败
  即断；鼠标关机/切走而接收器在位 = 静默超时断开，该端点以 ~500ms 快重试等
  设备回来（从未应答过的端点指数退避防握手风暴）。
- **connected 在 SN 识别完成后才上抛**（识别窗口自适应：无帧 3s / 有帧最长 8s，
  识别期间 SDK 主动下发 SN 查询；超时回退传输层临时身份 `"usb-xxxxxxxx"` /
  `"ble-<mac>"`，仅本次连接会话内稳定）。回调时序示例：

```
插上设备 → (SDK 内部探测/握手/识别) → um_on_connected(SN, UM_CONN_USB)
         → um_on_message(SN, {"type":"deviceInfo","sn":...})
设备切到蓝牙 → um_on_disconnected(SN, UM_CONN_USB) → um_on_connected(SN, UM_CONN_BLE)
拔走设备   → um_on_disconnected(SN, UM_CONN_BLE)
```

**RAW 规则的 SN 提取**：SDK 不解析自定义协议，需注册提取回调（init 前）：

```c
/* 识别窗口内 SDK 把收到的每帧原始数据交给本回调；识别出 SN 时写入 out_sn
 * 并返回 1。SN 必须每台设备唯一——是型号号则不要返回（两台会被并成一台）。 */
typedef int (*um_device_sn_probe)(const uint8_t* data, int len, char* out_sn, int out_cap);
void um_register_device_sn_probe(const char* rule_id, um_device_sn_probe cb);
```

未注册时该规则的设备在 3s 超时后以临时身份上线（`um_on_raw_frame` 照常工作）。

**按规则绑定握手/匹配回调**（多规则下区分设备类型；无后缀版本绑定默认规则）：

```c
typedef int (*um_usb_build_probe_ex)(const char* rule_id, uint8_t* out, int max_len);
typedef int (*um_usb_validate_resp_ex)(const char* rule_id, const uint8_t* buf, int len);
typedef int (*um_ble_match_device_ex)(const char* rule_id, const char* name, const char* address);
void um_register_usb_build_probe_for(const char* rule_id, um_usb_build_probe_ex cb);
void um_register_usb_validate_resp_for(const char* rule_id, um_usb_validate_resp_ex cb);
void um_register_ble_match_device_for(const char* rule_id, um_ble_match_device_ex cb);
```

**回调线程契约**：所有事件回调（connected/disconnected/message/audio/raw_frame）在 SDK 内部
**唯一的事件派发线程**触发——全局有序、**永不并发进入**（多设备事件也不会同时回调）。
回调内请勿阻塞、勿反调 `um_sdk_close`；指针参数仅回调期间有效。

**队列健康上报**（v0.3.0）：宿主消费不及时时，SDK 先淘汰最旧的音频/原始帧（实时流
泄压，离散事件永不淘汰）；丢弃发生期间经 `um_on_message` 限流上报（每 5s 至多一条，
**device_id 为空串 = 全局事件**）：

```json
{"type":"queueOverflow","evicted":12,"dropped":0}
```

`evicted` = 本周期淘汰的音频/原始帧数（正常防护，恢复消费即停）；`dropped` = 被丢弃的
离散事件数（宿主长时间卡死才会非零，须排查消费端）。

**语音音频源**（多设备下语音识别会话单源，运行中可随时切换）：

```c
/* 选定设备优先：仅该设备的音频经 um_on_audio 上抛，其它设备在 SDK 层静音。
 * NULL/空串 = 先到先得锁存（默认，v0.4.1 起）：首个出音频的设备占用本源
 * 直到其单次采集结束，期间其余设备静音；下一次采集重新先到先得。
 * 注意 NULL 不是"全部设备都出音频"。不校验在线状态，设备上线后自动适用。 */
int um_set_audio_source(const char* device_id);
const char* um_get_audio_source(void);   /* 空串 = 默认先到先得策略 */
```

**完整示例**见仓库 `demo/demo3.c`（默认规则 FULL + 第二规则 RAW 同时接入、SN 提取、
设备枚举与按 id 下发命令）。

## 六、事件协议（`um_on_message` 的 JSON）

所有离散事件统一为 `{"type":"...", ...}` 结构。**扩展性核心**：硬件未来升级只需新增 `type` 或字段，本协议结构保持稳定。

### 6.1 按键事件 `keyEvent`（核心）

```json
{"type":"keyEvent","key":"<key>","action":"<action>","index":<N>}
```

| 字段 | 说明 |
|---|---|
| `key` | 物理键名：`speech` / `translation` / `m` / `ai` / `capture` / `raw` |
| `action` | 动作：`down`（按下）/ `up`（抬起）/ `hold`（长按）/ `click`（单击） |
| `index` | **M 键专用**，第几个 M 键（从 1 起）；非 M 键为 0 |
| `code` | **raw 键专用**（v0.4.17）：原始键值（协议 data[5] 十进制原值） |

**键 × 动作全集：**

| 键 (`key`) | 支持动作 (`action`) | 说明 |
|---|---|---|
| `speech` | `down` / `up` | 语音键 |
| `translation` | `down` / `up` | 翻译键 |
| `m` | `down` / `hold` / `up` | M 键，`index` 指示第几个 M 键 |
| `ai` | `down` / `up` / `click` | AI 键 |
| `capture` | `click` | 截图键 |
| `raw` | `down` / `up` | **SDK 未接入键型的原始键值透传**（v0.4.17）：`action` 按协议配对惯例推断（奇码=down、偶码=up），集成方可按 `code` 自行配对/定义语义。心跳/电量/DPI/会议码不上抛 |

**示例：**

```json
{"type":"keyEvent","key":"speech","action":"down"}
{"type":"keyEvent","key":"m","action":"hold","index":1}
{"type":"keyEvent","key":"ai","action":"click"}
```

> 业务逻辑示例：收到 `{"key":"speech","action":"down"}` 时开始录音，收到 `action:"up"` 时停止并送识别；收到 `{"key":"m","action":"hold","index":1}` 时触发第一个 M 键对应的功能（截图/语音打字/回车等，由您定义）。

### 6.2 设备信息 `deviceInfo`

随心跳/音频上报，包含设备序列号、电量、连接类型、会议状态：

```json
{"type":"deviceInfo","sn":"000AEB20","battery":50,"deviceType":"usb","status":"normal"}
```

| 字段 | 说明 |
|---|---|
| `sn` | 设备序列号（十六进制字符串） |
| `battery` | 电量百分比（0–100，已钳制） |
| `deviceType` | 连接类型：`"usb"` 或 `"ble"` |
| `status` | 会议状态（v0.4.11，恒随帧下发）：`"normal"` / `"meeting"`。会议建立置 `meeting`；会议正常结束或**会议中连续 3 秒无音频流入**（设备开关复位/静默退出但链路未断——SDK 断流看门狗裁决）回 `normal`。断流裁决**不补发 `meetingDestroyed` 事件**——意外终止后由宿主决策续会（重新 `um_meeting_create`）或结束会议，宿主经 `status` 回落感知。宿主调用 `um_meeting_pause` 期间豁免裁决。 |

### 6.3 DPI 状态广播 `dpiChanged`

```json
{"type":"dpiChanged","level":2}
```

| 字段 | 说明 |
|---|---|
| `level` | 固件回报的档位字节（编码随固件族而异） |

> ⚠️ 本事件与 `um_set_dpi` **无关**——固件对软件 DPI 设置不回执（实测下发后零回报）。
> 触发源只有三种：硬件 DPI 键切档、连接建立、传输模式切换，且常连发 2~3 帧（重复
> 属正常）。软件设置的生效验证看光标速度。

### 6.4 会议状态

```json
{"type":"meetingCreated"}
{"type":"meetingDestroyed"}
{"type":"meetingBusy","owner":"<占用者SN>"}
```

`meetingBusy`：该设备的会议指令被拦截（会议被 `owner` 设备全局独占，命令返回值同时为 0）。

### 6.5 SDK 告警 `warning`（v0.4.6，统一信封）

`device_id` 为空串 = 全局事件。`text` 为可直接显示的完整中文句子；按 `code` 细分处理：

```json
{"type":"warning","code":"pairingBroken","text":"…","data":{"endpoint":"…","address":"…","name":"…"}}
```

| `code` | 含义 | `data` |
|---|---|---|
| `pairingBroken` | BLE 配对/加密态损坏（删除设备重新配对即愈；期间端点已隔离退避） | `{endpoint,address,name}` |
| `deviceCountHigh` | 在线设备总数超限（默认 >6 台） | `{total,limit}` |
| `bleLinkHigh` | 在线 BLE 链路数超限（默认 >1 条，即第 2 条起）——多活链挤占射频调度，部分固件鼠标语音投递自第 2 条活链起劣化，建议减链或改 USB/2.4G | `{ble,limit}` |

越界时各上抛一次（闩锁防重复）；回落到限值内后再次越界会重新上抛。

### 6.6 队列健康 `queueOverflow`

`device_id` 为空串 = 全局事件。宿主消费不及时时 SDK 先淘汰最旧的音频/原始帧（实时流泄压，离散事件永不淘汰），丢弃期间限流上报（每 5s 至多一条）：

```json
{"type":"queueOverflow","evicted":12,"dropped":0}
```

`evicted` = 本周期淘汰的音频/原始帧数（正常防护，恢复消费即停）；`dropped` = 被丢弃的离散事件数（宿主长时间卡死才会非零，须排查消费端）。

## 七、音频数据（`um_on_audio`）

音频输出由 `um_set_audio_output_mode` 决定：

### PCM 模式（`UM_AUDIO_PCM`，默认）

| 属性 | 值 |
|---|---|
| 编码 | 原始 PCM（无压缩头） |
| 采样率 | 16000 Hz（16 kHz） |
| 位深 | 16 bit（有符号小端） |
| 声道 | 单声道（mono） |
| 数据率 | 32 kB/s |

- 每次回调 `pcm` 指向一段解码后音频，`len` 为字节数；
- **指针仅在回调期间有效**，需要落盘/送识别请立即拷贝；
- 验证：把数据顺序写入 `xxx.pcm`，用 Audacity「导入原始数据」，选 `Signed 16-bit PCM / Little-endian / Mono / 16000 Hz`。

### RAW 模式（`UM_AUDIO_RAW`）

- 回调 `pcm` 为**原始编码累积块**（每 256 字节一块，未解码），格式由芯片决定（ADPCM/SBC）；
- 最终解码由调用方在 `um_on_audio` 回调中处理。

## 八、各平台注意事项

### 8.1 Windows

- **运行期依赖**：交付包已附全部运行期依赖（FFmpeg `avcodec-58.dll` / `avutil-56.dll` 与 VC++ 运行库副本），与 `uMouseSdk.dll` 同目录放置即可。DLL 所在目录不在系统默认搜索路径内——加载要点（PATH 前插 / `LoadLibraryExW` + `LOAD_WITH_ALTERED_SEARCH_PATH` / CRT 预载顺序与 System32 优先级陷阱）见**包内 README**；

- **BLE**：依赖系统自带 Bluetooth 协议栈（Win10/11 已内置），无需额外驱动；
- **智能屏幕/杀毒**：首次加载 dll 可能被拦截，加入信任即可。

### 8.2 Linux（UOS / 麒麟 / 方德 / 通用发行版）

> 本节适用于经商务渠道获取的信创 / 通用 Linux 交付包（本仓库不发布这些平台的包）。

**① USB 设备访问权限（重要）**

```bash

  | sudo tee /etc/udev/rules.d/70-umouse.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

> 不同型号设备请改 `idVendor`/`idProduct`（`lsusb` 查看）。蓝牙（BlueZ）通道不受此限制。

**② 运行期依赖**：动态链接 `libavcodec`、`libavutil`、`libudev`、`libdbus-1`（包名因发行版而异，以实际为准）。

```bash

```

**③ 蓝牙**：需 BlueZ 服务运行，部分发行版要求用户在 `bluetooth` 组。

### 8.3 macOS

- **运行期依赖**：交付包已附裁剪版 FFmpeg dylib（与主库同目录、`@loader_path` 互查），**无需安装 brew / FFmpeg**；
- **权限**：首次运行需授予「蓝牙」权限（USB / 2.4G 接收器连接无需任何授权）；
- **架构**：本仓库交付包为 Apple Silicon 原生 ARM64 构建；Intel（x86_64）版本请联系商务获取；
- **签名/公证**：把 `libuMouseSdk.dylib`（及随附 FFmpeg dylib）一并纳入签名。

## 九、线程模型与最佳实践

### 线程约定

- **所有回调在 SDK 内部唯一的事件派发线程触发**（非您的主线程；全局有序、不并发进入，多设备亦然，见 5.7「回调线程契约」）；
- `um_*` 接口内部对全局服务指针加锁，可从任意线程调用；但 `um_sdk_init` / `um_sdk_close` 建议由同一控制线程配对调用；
- 回调内可安全调用查询类接口（`um_get_device_count` / `um_get_connection_mode` 等）。

### 回调内严禁

- 长时间阻塞（同步网络请求、大文件读写）——会拖慢音频/事件上报导致丢帧；
- 反向调用 `um_sdk_close()`——会死锁；
- 持有重锁并与其他线程互等。

### 推荐模式：回调只拷贝，业务在工作线程处理

```c
static void on_message(const char* id, const char* json) {
    enqueue(&g_event_queue, strdup(json));   /* 只拷贝并入队，立即返回 */
}

void* worker_thread(void*) {
    char* json;
    while ((json = dequeue(&g_event_queue)) != NULL) {
        handle_business(json);   /* 这里可以慢 */
        free(json);
    }
    return NULL;
}
```

### 内存与生命周期

| 数据 | 有效性 | 处理建议 |
|---|---|---|
| `device_id`（回调参数） | 仅回调期间 | 需留存立即 `strdup` |
| `json`（on_message） | 仅回调期间 | 需留存立即 `strdup` |
| `pcm`（on_audio） | 仅回调期间 | 需留存立即 `memcpy` |
| `data`（on_raw_frame） | 仅回调期间 | 需留存立即 `memcpy` |
| `um_sdk_version()` 返回值 | 整个生命周期 | 静态字符串，可直接保存指针 |

### 退出流程

```c
um_sdk_close();   /* 幂等，停止线程、释放资源 */
/* close 之后不再有任何回调触发 */
```

## 十、常见问题（FAQ）

**Q1：没有触发 `on_connected`，`um_get_device_count()` 一直是 0。**
- 检查设备是否 USB 连接或蓝牙配对；
- Linux：检查 USB 权限规则是否已装（见 8.2）；
- 用 `um_sdk_init(1)` 打开日志查看探测过程。

**Q2：能收到 `on_connected` 但收不到音频。**
- 确认已注册 `um_register_audio`；
- 部分设备需先触发一次按键（如语音键）才开始推送音频流；
- 检查电量，低电量可能暂停音频。

**Q3：C# / Python 集成后闪退或「访问非法内存」。**
- 几乎都是回调委托被垃圾回收。把回调对象存为长期存活（字段/模块级变量），不要用临时变量注册。

**Q4：能否同时连接多个设备？**
- 支持多设备接入（v0.3.0 起多设备模型，v0.4.0 起每设备独立解析管线）：同型号多台共用一条规则，默认每规则 4 台、全局 8 台（`um_set_device_limit` 可调，详见 5.7）。

**Q5：SDK 内置 FFmpeg，商用许可是否有问题？**
- FFmpeg 以 **LGPLv2.1** 动态链接分发，满足「可替换」义务即可商用。**请勿静态化**，并随 SDK 发布物分发 `COPYING.LGPLv2.1`（本仓库根目录已附）。

**Q6：M 键按下后 SDK 会自动触发截图/语音吗？**
- 不会。SDK 只透传 `{"type":"keyEvent","key":"m","action":"down","index":1}`，做什么由您决定。

**Q7：不同国产化 Linux（UOS / 麒麟 / 方德）的包能互换吗？**
- 不建议。系统库版本可能不同，互换可能导致动态库加载失败。

**Q8：如何确认 SDK 正常加载？**
- 调用 `um_sdk_version()` 应返回 `"0.4.20"`；返回 NULL 或崩溃说明动态库未正确加载。

**Q9：什么时候用 RAW 模式？**
- 硬件协议与默认设备不同时。FULL 模式解析不了 → 用 RAW 模式透传原始帧自行解析。

## 附录 A：完整 C 示例（FULL 模式，含音频落盘）

```c
#include "umouse_sdk.h"
#include <stdio.h>
#include <string.h>

static FILE* g_pcm = NULL;
static long  g_pcm_bytes = 0;

static void on_connected(const char* id, int mode) {
    printf("[连接] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_disconnected(const char* id, int mode) {
    printf("[断开] %s via %s\n", id, mode == UM_CONN_BLE ? "BLE" : "USB");
}
static void on_message(const char* id, const char* json) {
    printf("[事件] %s %s\n", id, json);
}
static void on_audio(const char* id, const uint8_t* pcm, int len) {
    (void)id;
    if (g_pcm && pcm && len > 0) {
        fwrite(pcm, 1, (size_t)len, g_pcm);
        g_pcm_bytes += len;
    }
}

int main(void) {
    printf("声云智能鼠标 SDK demo, version %s\n", um_sdk_version());

    g_pcm = fopen("out.pcm", "wb");

    um_register_connected(on_connected);
    um_register_disconnected(on_disconnected);
    um_register_message(on_message);
    um_register_audio(on_audio);

    um_sdk_init(1);

    printf("运行中... 按回车结束。\n");
    getchar();

    um_sdk_close();

    if (g_pcm) {
        fclose(g_pcm);
        printf("PCM 已写入 out.pcm，共 %ld 字节。\n", g_pcm_bytes);
    }
    return 0;
}
```
